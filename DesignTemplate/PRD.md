# HearHealth 微信小程序 — 产品设计文档（PRD）

> 版本：v1.0（初稿）｜ 状态：评审中
> 设计系统参考：本目录 `apple-DESIGN.md` / `apple-tokens.json` / `apple-variables.css`

## 1. 产品概述

HearHealth 是一款用耳健康小程序，核心功能：

1. **用耳时长统计** — 记录并可视化每日/每周用耳时长与音量暴露
2. **听觉测试** — 纯音听阈自测（Web Audio API 生成 6 频率纯音），输出听力报告与护耳建议
3. **耳友圈社区** — 发帖/浏览/互动，分享听力报告与护耳经验
4. **护耳技能库** — 护耳科普文章列表与详情

> ⚠️ 免责声明贯穿产品：听觉测试结果仅供参考，不能替代专业医学检查。

> 📌 术语：「MVP」= 最小可行产品（Minimum Viable Product）——先做一版能跑通核心功能的最小版本，功能可简化、数据可用假的（演示数据），用来快速验证产品，验证通过后再迭代。本文档中所有「MVP」均为此意。

## 3. 主页面详述（12 个）

### 页面 1：首页（tab-首页，默认页）

定位：APP 启动默认页，三大功能的汇聚入口。

- 问候语 + 今日用耳时长**圆形进度环**（颜色随时长变化：安全绿 / 接近阈值黄 / 超阈值红）
- 两个快捷入口按钮：【开始听力测试】【查看护耳技能库】
- 今日健康提示卡片，根据当日使用时长提示
- 本周用耳概览**小型柱状图**（点击跳转统计页）
- 附近医院信息（下滑可见）
- 底部 4 Tab 导航

### 页面 2：统计页（tab-统计，主功能 1）

定位：用耳时长数据可视化中心。

- 顶部**日历**标注每日用耳时长（类似股票收益热力色块）
- 下方两个卡片：**耳机使用统计** / **环境音量统计**
- 卡片点击跳转对应详情（图表参照苹果方案：横轴时间、纵轴音量范围，顶部提供不同时间范围切换选项）
- 图表下方有详细说明：如 exposure、耳机型号等
- 底部 4 Tab 导航

### 页面 3：听觉测试引导页

定位：听觉测试入口，说明测试目的和环境要求。

- 返回按钮 + 标题「听力测试」
- 耳朵图标/插画
- 测试目的说明（明确标注「仅供参考，不能替代专业医学检查」）
- 环境要求清单：安静环境 / 有线耳机 / 将设备音量固定在舒适位置且测试中不调整 / 约需 5 分钟
- 【开始测试】按钮 + 【跳过本次】按钮

### 页面 4：听觉测试过程页（主功能 2 核心）

定位：核心测试交互，多步骤引导完成左右耳纯音听阈测试。

- Step 1：佩戴耳机确认（左右耳示意图 + 下一步按钮）
- Step 2：左耳测试（当前频率 + 相对强度百分比 + 播放按钮 + 【这一档听到了】【这一档没听到】按钮 + 频率进度）
- Step 3：右耳测试（同 Step 2）
- 顶部进度条（3 步）
- Web Audio API 播放纯音，6 个频率：125 / 250 / 500 / 1000 / 2000 / 4000 Hz
- 每个频率从小程序测试上限的 10% 开始，用户选择“没听到”后按 10% 逐级提高，记录第一次选择“听到了”的相对强度百分比；100% 仍未听到则记录为“测试范围内未测得”
- 百分比仅表示同一测试会话内的 Web Audio 线性数字增益相对值，不是等响度刻度。微信小程序无法读取设备系统媒体音量，且耳机、设备与系统音量均未校准，因此结果不得标注为 dB，也不支持跨设备直接比较

### 页面 5：听力报告结果页

定位：展示测试结果、评级和护耳建议，支持分享到社区。

- 返回按钮 + 标题「听力报告」
- 完成摘要卡片（测试时间 + 双耳已测得阈值数量；未校准结果不做医学等级评级）
- 左右耳“频率—相对强度阈值”**折线图**（纵轴为百分比，数值越低表示在本次设备与固定音量条件下越容易听到）
- 左右耳基础摘要（平均相对阈值、测得频率数量、6 个频率明细）与非医学性数据说明
- 测试日期、设备等信息
- 3 条个性化护耳建议（控制音量 / 定时休息 / 避免噪音）
- 【分享到耳友圈】【返回首页】按钮
- 底部免责声明小字

### 页面 6：耳友圈广场（tab-耳友圈，主功能 3）

定位：社区内容广场，浏览帖子和发布入口。

- 板块标签栏：全部 / 护耳妙招 / 用耳翻车 / 耳机安利
- 帖子卡片流：头像 + 昵称 + 时间 +「用户使用的设备」+ 标题 + 摘要 + 图片缩略 + 点赞/评论/收藏数
- 右下角悬浮发帖按钮（+）
- 底部 4 Tab 导航

### 页面 7：帖子详情页

定位：单条帖子完整内容 + 评论区。

- 返回按钮 + 板块标签
- 作者信息（头像 + 昵称 + 时间）
- 帖子标题 + 完整正文
- 互动按钮（点赞 / 收藏 / 分享）
- 评论列表（预置 5–8 条）
- 底部评论输入框 + 发送按钮

### 页面 8：发帖编辑页

定位：发布新帖子，支持从测试结果分享预填。

- 顶部操作栏（取消 / 发布帖子 / 发布按钮）
- 板块选择：护耳妙招 / 用耳翻车 / 耳机安利

- 内容多行输入框
- 字数统计（0/500）
- 添加图片按钮（MVP 提示「开发中」即可）

### 页面 9：个人中心（tab-我的）

定位：用户信息概览 + 各功能入口。

- 薄荷绿渐变顶部背景
- 用户信息（头像 + 昵称 + 简介）
- 数据概览卡片（累计用耳 / 测试次数 / 发帖数）
- 功能入口列表：我的帖子 / 护耳技能库 / 设置 / 关于我们
- 底部 4 Tab 导航

### 页面 10：护耳技能库列表页

定位：护耳科普文章列表，按分类筛选。

- 返回按钮 + 标题「护耳技能库」
- 分类标签：全部 / 日常护耳 / 耳机选购 / 噪音防护
- 技能卡片列表：封面 + 标题 + 摘要 + 分类标签 + 阅读量

### 页面 11：技能详情页

定位：单篇护耳文章完整内容。

## 5. 设计系统映射

| 设计文件 | 用途 |
|---|---|
| `apple-DESIGN.md` | 组件配方、Do's & Don'ts（主参考） |
| `apple-variables.css` | 改造为 `app.wxss` 全局 CSS 变量（WXSS 支持 `:root` 变量） |
| `apple-tokens.json` | 机器可解析的 token 源，用于校验/生成 |
| `apple-theme.css` | Tailwind v4 格式，小程序不可直接用（仅作取值交叉验证） |

**平台适配要点：**
- 设计 token 为 px（375px 设计宽），小程序需换算 **rpx**（1px ≈ 2rpx）
- SF Pro 仅 iOS 可用，安卓回退：`system-ui, -apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif`
- 主色 `#0066cc`（来自 design token `--color-primary`）；进度环状态色（安全绿/黄/红）、个人中心薄荷绿渐变等语义色**尚未在 DesignTemplate 中定义**，待补充到设计文件后再使用，禁止在代码里自造色值

## 6. 技术要点与决策记录

**已定决策：**
- [x] **数据层**：接云数据库（前端 SDK 直连 `wx.cloud.database()`），集合结构在开发时统一定义（字段名全组一致）
- [x] **用户体系**：MVP 免登录，本地默认用户（昵称「耳友」）；`login` 页删除
- [x] **现有模板页**：删除 `pages/example`、`pages/collab`、`pages/login`
- [x] **tabBar 图标**：MVP 先纯文字 tab（`iconPath` 可省略），后续补图标
- [x] **技术栈**：原生小程序（WXML/WXSS/JS），不引入 Taro/uni-app/Tailwind/npm 依赖
- [x] **分工方式**：按 4 个 tab 分组并行（页面路径：首页 `pages/home` / 统计 `pages/stats` / 耳友圈 `pages/community` / 我的 `pages/profile`），公共文件（app.json / app.wxss / utils）由框架负责人维护
- [x] **后端策略（现阶段只做前端）**：项目采用微信云开发，"后端"由微信提供（云数据库 / 云存储 / 云函数），**不需要自建服务器、不需要设计 REST 接口**。现阶段数据层用云数据库直连 + mock 兜底即可跑通全部页面；将来需要后端逻辑（如聚合统计、发帖校验）时，在 `cloudfunctions/` 里写云函数扩展（模板已内置 `event.type` 分发，返回统一 `{ success, data }`）
- [x] **统计类数据**：用耳时长、环境音量**不采集真实数据**，MVP 直接生成演示数据（按统计页需要的字段构造，如每日时长、音量分布），后续再迭代真实数据源

**待确认/待验证：**
- [ ] **Web Audio API**：基础库 ≥ 2.19.0 支持 `wx.createWebAudioContext()`，用 OscillatorNode 生成纯音；需真机验证音频输出（部分机型静音开关/声道限制）
- [ ] **云数据库权限与种子数据**：集合权限规则、`articles` 种子数据需在云开发控制台配置
